# Evals

This folder holds the evaluation set for the SaaS AI Support Agent.

## Files

- `questions.json` — 30 test questions (26 answerable, 4 off-topic / adversarial).
- `run.py` — runs all 30 questions through the RAG pipeline and writes results.
- `results/latest.json` — the last eval run (raw JSON, committed).
- `docs/EVALS.md` — human-readable report (generated by `run.py`).

## How to run

You need the demo articles ingested into a database first.

```bash
# From the api/ folder:
# 1. Start a local Postgres and ingest the articles (see README.md Phase 1 check).
# 2. Run the eval:
LLM_PROVIDER=fake python ../evals/run.py          # free, fast, no real AI answers
LLM_PROVIDER=cloudflare python ../evals/run.py    # real answers (needs Cloudflare keys)
```

The script writes `evals/results/latest.json` and updates `docs/EVALS.md`.

## What is measured

The eval only checks whether the bot **decided to answer or abstain**, not whether the answer is factually correct. Correctness checking requires a human reviewer or a separate LLM judge (not implemented yet).

| Metric | Meaning |
|---|---|
| Answered correctly | `should_answer=true` and the bot gave an answer |
| Abstained correctly | `should_answer=false` and the bot said "I don't know" |
| False positive | `should_answer=false` but the bot gave an answer (dangerous) |
| False negative | `should_answer=true` but the bot abstained (unhelpful) |

## Tuning MIN_SIMILARITY

Run the eval at several values of `MIN_SIMILARITY` (0.2, 0.3, 0.35, 0.4, 0.5) and
compare false positives and false negatives. Record the chosen value in
`docs/DECISIONS.md` D24 after the first real run.

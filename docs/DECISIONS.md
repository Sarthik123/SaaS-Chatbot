# Decisions

Every choice the AI coding tool made on the owner's behalf, with the alternatives and the reason.
The owner can overrule any of these; change the entry when that happens.

| # | Phase | Decision | Alternatives considered | Why |
|---|---|---|---|---|
| D1 | 0 | Use **Claude Code** (an AI coding tool by Anthropic) to write the code. The owner's `AGENTS.md` is the rulebook; `CLAUDE.md` contains one line, `@AGENTS.md`, so Claude Code reads the same rules. | OpenAI Codex | The owner's resume names Claude for this project. One tool per phase, commit before switching. |
| D2 | 0 | Keep the GitHub repository the owner actually created, `Sarthik123/SaaS-Chatbot` (private for now), instead of the guide's example name `saas-ai-support-agent`. | Create a second repo with the guide's name | The owner already created and connected this repo. A second repo would split the history. The guide says public is fine because no secrets are committed; making it public is the owner's choice (see NEXT-STEPS-FOR-OWNER.md). |
| D3 | 0 | Backend Python target is 3.11+. CI runs Python 3.12; the build environment used 3.13. | Pin one version | The guide asks for 3.11+. Running two versions in practice shows nothing is version-fragile. |
| D4 | 0 | The backend settings treat an **empty** environment value as "not set" and use the default. | Crash on empty values | `.env.example` ships with empty values; copying it must not break the app. The app must start even when keys are empty. |
| D5 | 0 | Secrets are stored as `SecretStr` in settings so printing the settings never shows them. | Plain strings | Prevents accidental leaks in logs. Covered by a test. |
| D6 | 0 | The test client uses `httpx2`, which the installed FastAPI/Starlette versions require for `TestClient`. | `httpx` | The packages installed in this environment recommend it. Used only in tests. |
| D7 | 0 | Website uses system fonts (no Google Fonts download). | Next.js Google fonts | Builds work offline and in CI; pages load faster. |
| D8 | 0 | Placeholder embedding size `EMBEDDING_DIM=384` until Phase 2. | Choose the real model now | Phase 2 is when the real embedding model is chosen from the provider's current list; the size must match it then. |
| D9 | 1 | Chunk first by headings, then by size (about 350 tokens, 50 overlap), exactly as `AGENTS.md` says. Small sections are **not** merged, so most chunks are one section long. | Merge neighbouring small sections up to 350 tokens | Follows the rulebook and gives precise matches. The risk: an answer that needs two sections may need more than one chunk. This is a candidate experiment for Phase 5 (merge small sections, compare the metrics). |
| D10 | 1 | Token counts are estimated by counting words and punctuation marks. | A real tokenizer package | No extra dependency and repeatable. The numbers are estimates, used only for sizing chunks. |
| D11 | 1 | Conversation and message ids are random UUIDs. Articles, chunks, feedback and tickets use plain numbers. | Numbers everywhere | A guessable conversation id would let one visitor write into another visitor's chat. |
| D12 | 1 | A help-request ticket keeps existing when its conversation is deleted (the link is cleared, `ON DELETE SET NULL`). | Delete the ticket with the chat | Deleting a chat should not silently delete a request a person deliberately sent to support. Tickets are removed by an admin action. Revisit in Phase 6 (privacy). |
| D13 | 1 | The keyword index (`tsv`) is a Postgres generated column built from heading + text with the English configuration. The meaning index is HNSW with cosine distance; the keyword index is GIN. | Fill `tsv` from Python; IVFFlat index | The database keeps `tsv` correct by itself. HNSW needs no training step and works on an empty table. |
| D14 | 1 | The repository interface has articles and chunks now. Search, conversation, message, feedback and ticket methods are added in the phases that need them, to both implementations, with contract tests. | Design the whole interface up front | Avoids guessing. Each addition is proven to behave the same in memory and in Postgres. |
| D15 | 1 | With no `DATABASE_URL` the app uses the in-memory repository. | Refuse to start | Keeps the "app must start with empty keys" rule and keeps tests and the end-to-end tests free. Deployments always set `DATABASE_URL`. |
| D16 | 1 | Database integration tests create a private schema per test and drop it afterwards. | Truncate tables in the real schema | They can never damage real data, even if `DATABASE_URL` points at a real database. |
| D17 | 1 | The demo articles use invented product names (Ledgerly, BookNest, PayLink) and the reserved `.example` domain. | Real brand names | The knowledge base must be 100% fake, with no real company content. |
| D18 | 1 | The embedding column size is fixed when the migration runs (`EMBEDDING_DIM`). | Unlimited vector column | An index needs a fixed size. Changing the embedding model to a different size later means recreating the chunks table and re-ingesting. |
| D19 | 1 | Local checks used Postgres 16 with pgvector 0.6.0 installed with apt; CI uses the `pgvector/pgvector:pg16` image, which is also what `docker-compose.yml` uses. | Docker locally | Docker was not available in the build environment. The same migration runs unchanged on both. |
| D20 | 2 | Default LLM: **Cloudflare Workers AI `@cf/mistral/mistral-7b-instruct-v0.1`** (free tier, instruction-following, responds in JSON reliably). Default embedding model: **`@cf/baai/bge-base-en-v1.5`** (768 dimensions, English-optimised, free tier). | OpenAI gpt-4o-mini + text-embedding-3-small (paid) | Cloudflare has a free tier and the owners do not need a credit card to test the full pipeline. Model list checked at cloudflare.com/developer-platform/workers-ai/ in October 2025. |
| D21 | 2 | The model is sent the **last 4 messages** (2 turns) of the conversation as history, each truncated to 600 characters. | Last 2 or last 8 | 4 messages covers one follow-up without making the prompt huge. The truncation stops a very long previous answer from dominating the prompt. |
| D22 | 2 | `retrieved_chunk_ids` in the `messages` table stores the ids of the top-5 chunks that were retrieved (all of them, whether or not the model cited them). | Store only the cited ids | Storing all retrieved ids lets admins replay the retrieval step when debugging, and lets the eval script judge the retrieval quality independently of the answer quality. |
| D23 | 2 | **OpenAI provider is written but untested against real keys** (no OpenAI key was available during development). Its unit structure matches the Cloudflare provider. | Skip it until Phase 5 | The interface hides the provider, so tests and the rest of the app do not care which one is used. Anyone who sets `LLM_PROVIDER=openai` can switch; the NEXT-STEPS-FOR-OWNER file says what to set. |
| D24 | 2 | `MIN_SIMILARITY` starts at **0.35**. The final tuned value will be recorded here after `evals/run.py` is run in Phase 5. | 0.5 (stricter) or 0.2 (looser) | 0.35 is the value stated in `AGENTS.md`. It will be adjusted once real answers are measured. |
